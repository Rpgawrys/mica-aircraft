1 · Interrogation
You ask one question. Two agents answer it from different places, and a third says where they agree, where they differ, and what the model is missing.

How a question gets answered

Structured path Unstructured path Reconciliation
Agent 1

Query the model of record

Goal: answer only from what the model holds, and show you the query it ran so you can check the answer yourself.

It turns your question into AQL, runs it, and shows you the query. It never reads a source document, so everything it returns already sits in the model.

Model: …, grounded in the live schema
Reads: aircraft_model graph via /_api/cursor
Guard: it checks the AQL is read-only and valid before running it
Agent 2

Ask the source material

Goal: find what the source documents say about the same question, including claims nobody has added to the model.

It sends your exact question to ArangoDB's GraphRAG retriever, which searches the document corpus and cites what it used.

Model: gpt-5.4 (ArangoDB-hosted retriever)
Reads: Aircraft KG Strong corpus via /v1/graphrag-query
Guard: a hedged source stays hedged. It never promotes a claim to fact
Agent 3

Reconcile and propose

Goal: separate what the model already holds from what only the documents carry, then propose specific edits.

It reads both answers and writes edit operations the app can apply. When the corpus is unreachable it proposes nothing and tells you why.

Model: …
Writes: only on analyst approval, via /_api/gharial
Guard: it adds rather than overwrites, and never changes a baseline value on its own
2 · Agentic change detection
Interrogation waits for you to ask. Change detection does not. A fourth agent works the backlog of source documents nobody has reviewed and tells you which ones move the model. Every document ends in one of five states, so you always know what is left.

How a source document becomes a model change

Agent step Waiting on you Written to the model
Step 1 · Detect

Find what nobody has reviewed

The agent lists every document in the corpus and subtracts the ones already marked reviewed. What remains is the backlog for the platform you picked.

When the backlog is empty the agent stops here. It does not call a model, and it does not bill you for a run that had nothing to read.

Watermark: ReviewedDocument in the structured database
Reads: Aircraft-corpus_sources
Step 2 · Compare

Read the documents against the model

The agent pulls the model's current state for that platform, including the real node keys, and hands both to Claude with the document text.

A document that restates what the model already holds counts as corroboration. The agent proposes nothing, and the document closes as reviewed.

Model: …
Guard: proposals must target a collection the schema defines
Guard: node keys come from the model, never from the agent
Step 3 · Queue

Hold the change for you

Each proposal lands in a durable queue with its source document, its confidence, and the exact graph operation it will run. The document gets its watermark.

The queue survives a restart. You can walk away mid-review and the backlog counts still add up when you come back.

Queue: UpdateProposal, status pending
Badge on the tab counts what is waiting
Step 4 · Decide

Accept or reject, then the counts move

Accepting runs the operation through the same write path the interrogation tab uses, stamped evidence_accepted so the source stays attached to the value. Rejecting leaves the graph alone.

Either way the document is reviewed, and it moves out of the backlog into the accepted or rejected count.

Writes: /_api/gharial, on your approval only
Provenance: every accepted change names the document it came from
